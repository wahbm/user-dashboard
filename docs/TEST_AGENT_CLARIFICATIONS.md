# 测试 Agent 待确认项答复

本文是对《01-需求测试分析》的项目确认口径，供测试 Agent 后续编写用例和执行验收使用；不是新的开发指令。附件中的“关卡状态：待确认”和“确认后进入需求评审”属于测试 Agent 项目流程，本项目不会因读取该文档自动进入下一阶段。

## 当前结论

本期只实现管理员后台和普通用户管理，不实现普通用户登录。当前代码已补充写操作幂等和前端重复提交保护；除下文明确列出的产品边界外，测试可以按当前实现作为验收基准。

## 本轮已完成的补强

- 除登录和退出登录外的受保护写接口必须携带 `Idempotency-Key`：新增、编辑、状态切换、重置密码。
- 服务端在 `admin_idempotency_keys` 中保存管理员、请求 key、请求摘要和最终响应，记录有效期为 24 小时。
- 相同管理员使用相同 key、相同方法、路径和请求体重试，会回放第一次的 HTTP 状态和响应体。
- 同一 key 被复用于不同请求时返回 `1001`；缺少或超长 key 也返回 `1001`。
- 前端新增、编辑、状态切换和重置密码都会生成 key；新增和编辑表单的确定按钮在提交期间显示 loading 并禁止重复提交。退出登录通过服务端吊销 Token 处理，未纳入幂等回放。
- 同一用户使用不同 key 重复新增时，仍会按正常唯一约束返回 `2002` 或 `2003`，这是不同业务请求，不属于同一幂等重试。

以上幂等补强已写入当前工作树，但本轮没有执行提交或部署；线上环境要在下一次发布时先完成数据库迁移，线上 Swagger 和接口行为随后才会同步更新。

## 待确认项答复

### 1. 普通用户登录链路

当前 `/api/login` 只认证 `admin_accounts`，没有普通用户登录页或普通用户登录接口。`users` 表中的密码字段只用于当前用户管理数据模型。

因此，禁用普通用户后是否不能登录、重置密码后普通用户能否登录，目前不属于本系统可执行的测试范围。若未来需要验证，必须补充普通用户认证系统、入口、接口，以及禁用对已有登录态的影响规则。

### 2. Token 生命周期

- 默认有效期为 24 小时，可由 `TOKEN_TTL_SECONDS` 配置。
- 没有刷新 Token 机制。
- 前端保存于 `localStorage.admin_token`。
- 服务端只保存 SHA-256 摘要、过期时间和吊销时间。
- 退出登录会吊销当前 Token。
- 过期、吊销、管理员被禁用或缺少 Bearer Token 时返回 `1003`。
- 前端在受保护接口收到 `1003` 后清除本地凭据并跳转登录页。

当前没有定时主动检测；失效会在下一次受保护接口请求时发现。测试应按“请求触发失效处理”验收。

### 3. 全部状态和分页

- 状态为“全部”时省略 `status` 参数。
- 查询条件之间使用 AND。
- `page` 从 1 开始，必须大于等于 1。
- `pageSize` 只允许 10、20、50。
- 分页参数缺失、格式错误或超出允许值返回 `1001`。
- 页码超过总页数时返回空列表，不自动回退到最后一页。
- 前端查询、重置和 pageSize 变化会回到第 1 页。

### 4. 姓名和邮箱规则

- 姓名长度为 2～20 个字符；当前没有额外限制空格、中文或特殊字符。
- 后端使用 `Array.from` 计算姓名长度。
- 邮箱可以为空；非空时按当前邮箱正则校验。
- 数据库邮箱字段上限为 254 字符，但接口层尚未单独定义最大长度规则。

如果验收必须覆盖严格邮箱规范或统一 Unicode 长度定义，需要先补充产品规则；当前测试不要自行扩大限制。

### 5. 编辑接口的只读字段

`PUT /api/users/{id}` 只接受 `name`、`mobile`、`email`。传入 `username`、ID、创建时间、密码或其他额外字段时，由严格参数校验返回 `1001`，不会静默忽略。

### 6. 状态接口边界

- `status=0` 表示禁用，`status=1` 表示启用。
- 其他状态值返回 `1001`。
- 对相同状态重复设置会返回成功，视为幂等业务操作。
- 用户不存在返回 `2001`。
- 管理员与普通用户分表，状态接口不操作管理员，因此“管理员操作自身”和“最后一个管理员”规则不适用。

### 7. 页面提示与接口 message

接口成功响应可以使用通用 message“操作成功”；前端根据动作显示“启用成功”或“禁用成功”。测试应分别校验接口 `code=0` 和页面最终提示，不要求两者文案完全相同。

### 8. HTTP 状态码和 data

- 业务成功及大多数业务错误使用 HTTP 200，通过 `code` 区分。
- 系统异常 `9999` 使用 HTTP 500。
- 错误响应的 `data` 为 `null`。
- 编辑、状态切换、重置密码和退出登录成功时，`data` 为 `null`。
- 无数据列表返回 `list=[]`、`total=0`。
- `createTime` 返回 `YYYY-MM-DD HH:mm:ss` 字符串。

当前没有显式的 UTC/Asia/Shanghai 时区转换；跨时区测试需要先确定时区契约，不应直接把运行环境时区当成产品规则。

### 9. 数据库核验方式

数据库结构来源为 `server/sql/001_init.sql`，当前包含：

- `admin_accounts`
- `users`
- `admin_sessions`
- `admin_idempotency_keys`

没有生产数据库只读凭据提供给测试 Agent 时，应以 API 写入后再次查询、页面刷新和列表结果作为一致性证据。若要求验证底层字段，需要另行提供脱敏测试数据库和只读账号，不能使用生产密码。

### 10. 重置密码和安全范围

`POST /api/users/{id}/reset-password` 不需要请求体，成功后密码统一重置为 `Aa123456`，服务端以 bcrypt 哈希存储；用户不存在返回 `2001`。

当前系统没有普通用户登录接口，所以只能验证接口成功、后续列表/数据状态和受控哈希变化，不能在本系统内验证普通用户登录生效。固定重置密码的安全专项评估仍不在本期范围。

## 测试请求约定

除 `POST /api/login` 外，所有受保护接口都需要：

```text
Authorization: Bearer {token}
```

除退出登录外，所有受保护的 `POST`、`PUT`、`PATCH` 写接口还需要：

```text
Idempotency-Key: {unique-request-id}
```

在线 Swagger 文档：<https://8.130.116.192/ww/user-dashboard/api-docs/>。可以先登录取得 Token，再在 Swagger UI 的 `Authorize` 中填入 Token，并为每次写操作提供新的 key。

## 仍需产品确认的事项

- 是否未来增加普通用户认证系统，以及禁用用户已有会话如何处理。
- 邮箱最大长度、邮箱格式标准和姓名字符计数规则。
- `createTime` 的正式时区约定。
- 测试是否需要数据库只读核验，还是接受 API + 页面二次查询作为一致性证据。
